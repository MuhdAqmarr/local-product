# LokalLah! — English / Bahasa Melayu (i18n) spec

Owner's decision: **English is the default**; Bahasa Melayu is one tap away. Both languages are
prerendered statically (no request-time rendering, same speed as today).

## URLs

| Language | Home | Promos | Brand |
| --- | --- | --- | --- |
| English (default) | `/` | `/promos` | `/brands/christy-ng` |
| Bahasa Melayu | `/ms` | `/ms/promos` | `/ms/brands/christy-ng` |

- `/en` and `/en/...` permanently redirect (308) to the unprefixed URL (one canonical URL per page).
- Internally every page lives under `src/app/[lang]/` with `lang ∈ {"en","ms"}`; `src/proxy.ts`
  rewrites unprefixed paths to `/en/...` (the browser never sees `/en`).
- Language choice is remembered in the `lokallah-lang` cookie (1 year). Only the bare home `/`
  redirects to `/ms` when that cookie says `ms`; every other URL is honoured as-is, so shared links
  open in the language they were shared in.
- No `Accept-Language` sniffing: English is the default for everyone.

## Routing layout

```
src/app/
  [lang]/
    layout.tsx            root layout: <html lang="en-MY" | "ms-MY">, generateStaticParams → en, ms
    page.tsx, loading.tsx, not-found.tsx, error.tsx, opengraph-image.tsx, twitter-image.tsx
    promos/ new/ brands/ brands/[slug]/ categories/[slug]/ saved/ about/   (moved as-is)
  api/**                  unchanged (route handlers, language-neutral JSON)
  sitemap.ts robots.ts manifest.ts favicon.ico icon/apple-icon   stay at the app root
  global-error.tsx        stays at the root (minimal, bilingual text)
```

- Nested `generateStaticParams` (brands, categories) keep returning only their own param; the
  root `[lang]` param is combined automatically. Read the locale with `lang()` from
  `next/root-params` (Server Components and server utilities only; it also keys `'use cache'`).
- `src/proxy.ts` keeps today's slug check (unknown brand/category slug → real 404) and adds the
  locale rules above. It must skip `/_next`, `/_vercel`, `/api`, `/icon`, `/apple-icon` and exactly the
  app-root files `/favicon.ico`, `/sitemap.xml`, `/robots.txt`, `/manifest.webmanifest` (there is no
  `public/`); every other dotted path (`/x.html`) goes through the page check and gets a real, branded 404.

## Code layout

```
src/i18n/
  config.ts        LOCALES, DEFAULT_LOCALE, Locale, hasLocale(), localeHref(locale, path),
                   stripLocale(pathname) → { locale, path }, htmlLang(locale), ogLocale(locale)
  server.ts        getLocale() (lang() + hasLocale guard), getDictionary() → full dictionary,
                   getMessages(...namespaces) → subset for client providers
  client.tsx       "use client": I18nProvider({ locale, messages }), MessagesProvider({ messages })
                   (nested, merges namespaces), useI18n() → { locale, m, href(path), fmt }
  format.ts        fmt(template, vars) — "{count} promos"; plural(n, { one, other }) → string
  dictionaries/
    en/  common.ts home.ts listings.ts brands.ts categories.ts search.ts saved.ts about.ts errors.ts meta.ts
    ms/  same files; each ms file is typed `satisfies` the en shape (missing keys fail tsc)
```

Rules:
- **Messages are plain strings** (client-safe, serialisable). Variables use `{name}` placeholders and
  `fmt()`; English plurals use `{ one, other }` objects with `plural()`. No functions in dictionaries.
- Server Components: `const t = await getDictionary()` then `t.home.heroTitle`.
- Client Components: `const { m, href } = useI18n()`; the layout provides `common` + `search` +
  `saved` to `I18nProvider`; a page wraps its client islands in `MessagesProvider` with its own
  namespace (e.g. `listings`).
- **Every internal link is locale-aware**: server → `localeHref(locale, "/promos")`, client →
  `href("/promos")`. No hard-coded `href="/..."` for pages (API/asset URLs are language-neutral).
- Dates and relative time take the locale: `timeAgo(iso, now, locale)` → "3 hours ago" /
  "3 jam lepas"; `formatDate`/`formatClock` likewise. Prices are the same in both.

## Content

- **English (default)**: warm, playful, clear English for Malaysians and visitors — light local
  flavour where it feels natural ("Jom", "lah!" sparingly), never broken English.
- **Bahasa Melayu**: the existing Manglish copy deck in docs/DESIGN.md §9 (natural, casual Malay
  with everyday English loanwords).
- Keep these names in both languages: **LokalLah!**, **Cili Padi**, **Naik Daun**, **Jenama Ikon**,
  **Oyen**. In English, explain them once where they appear (e.g. "Cili Padi — small but mighty").
- Data:
  - categories: `name` (EN) / `nameMs`; blurbs as `blurb` (EN) / `blurbMs`;
  - tiers: `tagline` + `description` in both languages;
  - brand descriptions are English in `src/data/brands.json`; Malay versions live in
    `src/data/brands-ms.json` (`{ "<slug>": "<≤160 chars>" }`), read through
    `brandDescription(brand, locale)` — that file survives `npm run brands` re-runs;
  - product titles come from the stores and are shown as-is.

## Language toggle

`LanguageToggle` (client): a compact sticker-style **EN | BM** pill, in the desktop header right
cluster, the mobile header and the footer. It sets the cookie, then navigates to the same page in
the other language (keeping query string and hash) with `router.push` inside a transition. It has
`aria-label="Language / Bahasa"`, each option has `lang` + `hreflang`, and the current one is
`aria-current="true"`.

## SEO and social

- `<html lang>`: `en-MY` / `ms-MY`.
- Every page's metadata: localized title/description; `alternates.canonical` (its own URL) and
  `alternates.languages` = `{ en, ms, "x-default": en }`; Open Graph `locale` = `en_MY` / `ms_MY`
  with `alternateLocale`; the default OG/Twitter image is localized (headline in that language);
  per-brand OG images localize their small labels (category name, counts); tier names stay.
- `sitemap.ts` lists both versions of every URL with `alternates.languages`.
- The social preview audit (`og-audit.mjs`) must pass for both languages.

## How to (the API as built)

### Files

```
src/i18n/
  config.ts     client-safe: LOCALES, DEFAULT_LOCALE, Locale, hasLocale, otherLocale, localeHref,
                stripLocale, htmlLang, ogLocale, intlLocale, languageAlternates, LOCALE_COOKIE, LOCALE_LABEL
  format.ts     client-safe: fmt(template, vars), plural(n, forms, vars?), pluralForm(n, forms), Plural, MaybePlural
  rich.tsx      hook-free: rich(template, { name: <node> }) → ReactNode (markup inside one translated sentence)
  server.ts     getLocale(), getDictionary(), getMessages(...ns), dictionaryFor(locale), messagesFor(locale, ...ns)
  client.tsx    I18nProvider, MessagesProvider, useI18n(), useLocale(), useLocalePath(), useLocaleRouter()
  link.tsx      Link (drop-in next/link that localizes href), localizeHref(locale, href)
  shared.ts     commonFor(locale): the `common` namespace synchronously (hook-free components)
  dictionaries/en/*.ts   source shape: `const x = {…}; export default x; export type XMessages = typeof x;`
  dictionaries/ms/*.ts   `const x = {…} satisfies XMessages;` (a missing or extra key fails tsc)
src/components/layout/language-toggle.tsx   LanguageToggle({ variant?: "header" | "compact" | "footer" })
```

Namespaces and owners: `common` (shared layer: header, tab bar, Kategori, footer, feedback, product /
brand / category / rail components), `errors` (404 + error frame), `meta` (site defaults + default
social card; page agents add their page keys, e.g. `meta.promos.title`), and `home`, `listings`,
`brands`, `categories`, `search`, `saved`, `about` (created empty; each page agent fills its own).
Add a key to `en/<ns>.ts` first, then the same key to `ms/<ns>.ts`; `npx tsc --noEmit` tells you what
is missing.

### Server Components (pages, sections)

```tsx
import { getDictionary, getLocale } from "@/i18n/server";
const [locale, t] = await Promise.all([getLocale(), getDictionary()]);
<h1>{t.home.heroTitle}</h1>
<p>{fmt(t.home.heroSub, { brands: stats.brands })}</p>
<ProductCard product={p} locale={locale} syncedAt={stats.syncedAt} />
```

`getLocale()` reads `lang()` from `next/root-params` (works in any server component, server utility,
`generateMetadata` and metadata image files; not in Client Components, Server Actions or Route Handlers).
A sync helper component in a page can simply be made `async` and call `getLocale()` itself.

### Metadata (every page)

```tsx
export async function generateMetadata(): Promise<Metadata> {
  const locale = await getLocale();
  const t = dictionaryFor(locale).meta;
  return pageMetadata({ locale, title: t.promos.title, description: t.promos.description, path: "/promos" });
}
```

`pageMetadata` (`@/lib/site`) takes the language-neutral `path` and returns title, description,
`alternates.canonical` (own URL) + `alternates.languages` ({ en, ms, x-default }), Open Graph
(`locale`, `alternateLocale`, `url`, localized default image) and a large Twitter card. Options:
`socialTitle`, `socialDescription`, `absolute` (Home), `defaultImage: false` (routes with their own
opengraph-image, i.e. brand pages), `extra` (e.g. `{ robots: { index: false } }`). The root layout sets
`authors` / `creator` / `publisher` = MaqmarX for every page. The default card is
`/opengraph-image` · `/ms/opengraph-image` (headline from `meta.og`); `not-found.tsx` only accepts
static metadata, so its title is bilingual.

### Client Components

```tsx
"use client";
import { useI18n } from "@/i18n/client";
const { m, locale, href, fmt, plural } = useI18n();
<button aria-label={m.common.backToTop} />
toast({ message: plural(n, m.common.live.newSync) });
```

- The root layout provides `common`, `search`, `saved`. Any other namespace must be provided by the
  page around its islands: `<MessagesProvider messages={await getMessages("listings")}>…</MessagesProvider>`.
  In development a missing namespace throws a clear error.
- Files that `import * as m from "motion/react-m"` must not destructure `m` from `useI18n()`:
  write `const t = useI18n().m.common.feedback` instead.
- Active-link checks: `useLocalePath()` ("/ms/promos" → "/promos"), never raw `usePathname()`.
- Programmatic navigation: `useLocaleRouter()` (push/replace/prefetch localize the path).

### Links

- `import { Link } from "@/i18n/link"` everywhere instead of `next/link` (already swapped across the
  codebase). It localizes `href` from context and is idempotent (an already-prefixed href is fine).
  `Button`, `Chip`, `IconButton`, `StretchedLink`, `SectionHeader`, `ShellLink`, `BrandLink`,
  `EmptyState` actions and toast actions all go through it, so pass **language-neutral** paths:
  `href="/promos"`, `href="/brands?tier=ikon"`, `href="/about#sync"`.
- Only the language toggle links across languages (it uses `next/link` directly).
- Server code that needs the string: `localeHref(locale, "/promos")`.

### Hook-free shared components (render on server and client)

These take a required `locale` prop (tsc reports every missing one): `ProductCard`, `ProductRow`,
`ProductGrid`, `Price`, `BaruSticker`, `DealGroupHeader`, `KalendarKoyak` (+ `dayLabel(iso, ref, locale)`),
`BrandCard`, `BrandCounts`, `BrandCollage`, `TierCop`, `CategoryTiles`, `RailEndCard`; also
`priceSentence(p, locale)` and `jimatText(p, locale)`. Server: `await getLocale()`; client: `useI18n().locale`.

These server-only components are `async` and read the locale themselves (no prop, Server Components
only): `LivePill`, `Rail`, `SectionHeader`, `CategoryTile`, `TierStamp`,
`SiteHeader`, `Footer`, `Logo`, `CategoryPopover`, `SkipLink` (and anything that renders them, e.g. `CategoryShelf`).

### Nouns and plurals

`Rail`, `LoadMore` and `ProductFeedMore` take `noun?: MaybePlural`: pass `{ one: "promo", other:
"promos" }` from the dictionary (Malay repeats the same word). Templates with markup use `rich()`:
`rich(pluralForm(n, t.common.product.groupCount), { count: <b className="font-num">{n}</b> })`.

### Data and formatting

- Categories: `categoryLabel(slugOrCat, locale)` (short: "Beauty" / "Kecantikan", for tiles, chips,
  nav), `categoryName(…)` (full: "Skincare & Beauty" / "Kecantikan", for headings and metadata),
  `categoryBlurb(…)`. Raw fields: `name`, `nameShort`, `nameMs`, `blurb`, `blurbMs`.
- Tiers: `tierCopy(tier, locale)` → `{ name, tagline, description, line, ring }` (names never change).
  Raw fields: `tagline/taglineMs`, `description/descriptionMs`, `line/lineMs`, `ring/ringMs`.
  (`TIER_COPY` was removed; use `tierCopy`.)
- Deal groups: `dealGroupLabel(level, locale)` ("Crazy savings" / "Jimat gila").
- Brands: `brandDescription(brand, locale)` (`@/lib/brands`, server only) reads `src/data/brands-ms.json`
  and falls back to English. Localize on the server before passing `description` to `BrandCard` or a
  client island (never import `@/lib/brands` into client code: the JSON is large).
- Time: `timeAgo(iso, now, locale)`, `formatClock(iso, locale)`, `formatDate(iso, locale)`,
  `formatDateTime(iso, locale)` ("9 Oct 2026, 3:40 PM" / "9 Okt 2026, 3:40 PTG"), `SYNC_COPY[locale][state]`,
  `MONTHS_SHORT[locale]`. All built from fixed tables + numeric Intl parts, so server and browser agree.
  `RelTime` takes `template` ("Launched {time}") and reads the locale itself.

### Proxy and new pages

`src/proxy.ts` knows every page path (`PAGES` + brand/category slug rules) and rewrites anything else
to the localized 404 with a real 404 status. **Adding a page means adding its path there.** The
`[lang]/[...missing]` catch-all only exists to render `[lang]/not-found.tsx` for those rewrites.
